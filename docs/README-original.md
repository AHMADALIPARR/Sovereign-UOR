# Sovereign UOR

**Inverted monorepo** of two independent sovereign stacks that share a claim discipline and nothing else.

| Tree | Language | Purpose |
|------|----------|---------|
| `src/` (root) | Scala 3 + GraalVM | Canonical sparse multivariate polynomials over \(\mathbb{Z}/2^{64}\mathbb{Z}\) with native-image FFI for BQN and C |
| `montrepol/` | Haskell (Cabal) | Exact mathematics in which every claim is tied to a test that can fail |

[![CI](https://github.com/AHMADALIPARR/Sovereign-UOR/actions/workflows/ci.yml/badge.svg)](https://github.com/AHMADALIPARR/Sovereign-UOR/actions/workflows/ci.yml)

### Root

| Path | Role |
|------|------|
| `.github/workflows/ci.yml` | Builds both stacks. Scala job compiles the kernel, runs munit, and produces `libuor.so`. Cabal job runs `cabal build all`, `cabal test all` and `cabal run mp-gate` inside `montrepol/`. |
| `.github/workflows/honesty.yml` | Replays the planted mutants listed in `montrepol/model/mutants.toml`. Each mutant must be caught by the tests it names. |

| `README.md` | This document. |

| Path | Role |
|------|------|

### montrepol (Haskell exact mathematics)

`montrepol/` is a self-contained Cabal monorepo. It depends on nothing but GHC: `cabal.project` sets `active-repositories: :none`. The test harness, PRNG, TOML reader and every algorithm are written here.

| Path | Role |
|------|------|

| `montrepol/CONFORMANCE.md` | Generated by `cabal run mp-gate -- write`. Do not edit. Contains the rendered claim register. |
| `montrepol/AGENTS.md` | Instructions for automated agents and human contributors. |
| `montrepol/VERIFICATION.md` | Describes the verification methodology (R1–R6, mutant replay, oracles). |

#### Model (`montrepol/model/`)

The claim register. Every ID that appears in a test must be registered here; every registered ID must have at least one test.

| Path | Role |
|------|------|
| `model/ids.toml` | Conformance ID register. Each entry has an ID, package, level (`build` or `some-true`), claim text and oracle description. |
| `model/authorities.toml` | Bibliography of external authorities cited by claims. |
| `model/ledger.toml` | Claims that have no test (reproduced facts and measured quantities). |
| `model/mutants.toml` | Planted defects used by the honesty workflow. Each mutant names the file, the text to replace, and the tests that must catch it. |

## Building and testing

### Scala

```bash
# JVM tests
scala-cli test src/main/scala/uor/kernel src/test/scala/uor/kernel/Poly64Test.scala

# Native shared library
mkdir -p build
scalac -d build src/main/scala/uor/kernel/*.scala src/main/scala/uor/ffi/UorExports.scala
native-image --shared -cp build -H:Name=libuor -O3 --no-fallback
```

### Haskell

```bash
cd montrepol
cabal build all
cabal test all
cabal run mp-gate
cabal run mp-gate -- mutants
```

## Design principles

The repository is deliberately inverted. The Scala kernel lives at the root because it is the production artefact that other systems link against. The Haskell monorepo lives in a subdirectory because it is a verification and reference implementation whose only external dependency is the compiler.

Both stacks enforce the same claim discipline:

1. Every public claim is registered.
2. Every registered claim is discharged by a test that can fail.
3. A gate checks the bijection between the register and the tests.
4. Planted defects are replayed to prove the gate is not vacuous.

The Haskell side realises this discipline with four TOML files and a pure library (`mp-gate`). The Scala side realises it with munit properties and the native-image build.

## Package dependency graph (Haskell)

```
mp-gate
  ├── mp-check
  └── (reads model/ and packages/* at runtime)

mp-linalg ──┐
mp-lie    ──┼── mp-check
mp-seq    ──┤
mp-analytic─┘
```

`mp-check` is the only package that every other package depends on. It supplies the generators, the result type and the suite runner. All other dependencies are internal; the Cabal project forbids external repositories.

## Conformance levels

| Level | Meaning | Example |
|-------|---------|---------|
| `build` | Constructed in this repository and checked against an oracle. | Bareiss determinant equals the Leibniz expansion (LA-04). |
| `some-true` | Reproduced from an external authority; not established here. | Strassen’s asymptotic exponent (ledger). |
| `open` | No test exists. Appears only in the ledger. | Truncation error of the explicit formula. |

An ID in `ids.toml` is never `open`. An open claim lives in `ledger.toml` and is rendered under the Ledger section of `CONFORMANCE.md`.

## Mutant replay

`model/mutants.toml` lists thirteen planted defects. The honesty workflow:

1. Replaces a unique fragment of source with a defective version.
2. Runs the named test suite.
3. Restores the original source.
4. Requires that the suite fails and that the failure message contains the expected diagnostic.

A mutant that is not caught, or that is caught by the wrong rule, fails the honesty job. This is the only evidence that the gate is not vacuous.

## Adding a new claim

1. Add an entry to `montrepol/model/ids.toml` with a fresh ID, the package, the level, the claim text and the oracle description.
2. Write a test in the corresponding package whose first argument is that ID.
3. Run `cabal run mp-gate -- write` to regenerate `CONFORMANCE.md`.
4. Commit both the source change and the regenerated `CONFORMANCE.md`.

The gate will reject the pull request if any of these steps is omitted.

## Scala kernel public surface

The shared library exports three entry points:

| Symbol | Signature | Purpose |
|--------|-----------|---------|
| `uor_d64_transform_inplace` | `(thread, ptr, len, stride, direction) -> void` | In-place dihedral transform. |
| `uor_strata_histogram` | `(thread, ptr, len, out[65]) -> void` | Population count histogram of the transformed vector. |
| `uor_poly64_canonicalize` | `(thread, vars, nterms, terms, out) -> int` | Canonicalise a sparse polynomial and return its SHA-256 digest. |

All three are thread-safe provided each thread owns its own isolate. The BQN example above demonstrates the isolate creation protocol.

## Versioning

The repository follows a single version line. The Haskell packages declare the same version in their `.cabal` files. The Scala kernel does not yet publish a versioned artefact; the native image is built from the tip of `main`.

## Contributing

- Keep the claim register and the tests in lock-step.
- Do not add external dependencies to the Haskell monorepo.
- Do not edit `CONFORMANCE.md` by hand.
- Run both the Cabal gate and the honesty workflow before opening a pull request.
